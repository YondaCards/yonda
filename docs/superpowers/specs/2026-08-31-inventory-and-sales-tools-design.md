# Инвентаризация и корзина продаж для Yonda Cards — дизайн

## Контекст

Yonda Cards — домашнее производство открыток, альбомов и интерактивных книг
(Ташкент, сум). Продажи идут через Instagram, индивидуальные заказы и пять
офлайн-точек на консигнации (Teplo Store TAS, Teplo Store SKD, Human House,
UzPost, Ethno Gallery). У бизнеса уже есть рабочий инструмент управленческого
учёта — Google Таблица "test Yonda фин учет", связанная с Google-формой
"Учет Yonda Cards" и несколькими Apps Script автоматизациями (Telegram-бот,
уведомления о заказах, автосписание материалов при производстве).

Таблица активно используется (899+ строк в журнале операций), но два процесса
в ней неудобны, из-за чего фактически не используются на практике. Эта работа
— два новых мобильных инструмента поверх существующей таблицы, без замены
самой системы учёта.

## Текущая система (по состоянию на 31.08.2026)

### Листы таблицы

| Лист | Назначение |
|---|---|
| Заказы клиентов | Ответы формы заказов (Instagram, имя, телефон, адрес, заказ, дата/время доставки) |
| План Производства | Плановое количество товаров → расчёт потребности в материалах |
| Реестр материалов | Журнал движений материалов: Дата, Материал, Тип (Приход/Списание), Количество, Примечание |
| Склад материалов | Остатки материалов, формула `СУММЕСЛИМН(Приход) − СУММЕСЛИМН(Списание)` по каждому материалу. Без разбивки по локациям. |
| Склад товаров | Остатки товаров по локациям (Основной склад + 5 точек), формула — см. ниже |
| Реестр товаров | Журнал движений товаров: `# ID, Дата, Тип записи, Товар, Количество, Тип, Откуда, Куда` (колонки A–H) |
| Ответы на форму (1) | Сырые ответы Google-формы "Учет Yonda Cards" (ветки: Продажа/Расход/Доход/Переводы/Учёт товаров) |
| P&L | Дашборд доходов/расходов с фильтром по датам |
| Операции | Единый денежный журнал: ID, Время, Тип (Доход/Расход/Переводы), Сумма, Счёт, Категория, Количество, Примечание |
| Сводная таблица 2 | Сводная по доходам/расходам |
| Счета | Остатки по счетам (Наличка, Paynet, Личная карта, Расчётный счёт) |
| Справочники | Справочник цен, Тип оплаты→Счёт, Категории расходов, Точки продаж, BOM (спецификации товаров, столбцы M:P) |

### Формула остатка «Склад товаров» (на каждую ячейку Товар×Локация)

```
=СУММЕСЛИМН(Кол-во; Товар; Тип="Производство"; Куда=локация)
+СУММЕСЛИМН(...; Тип="Перемещение"; Куда=локация)
+СУММЕСЛИМН(...; Тип="Возврат"; Куда=локация)
+СУММЕСЛИМН(...; Тип="Заказ у поставщиков"; Куда=локация)
−СУММЕСЛИМН(...; Тип="Перемещение"; Откуда=локация)
−СУММЕСЛИМН(...; Тип="Продажа"; Откуда=локация)
−СУММЕСЛИМН(...; Тип="Возврат"; Откуда=локация)
```

### Google-форма "Учет Yonda Cards" — текущие ветки

- **Продажа**: Товар (один!), Количество, Тип оплаты, Примечание. Без точки/канала, без цены.
- **Расход**, **Доход**, **Переводы**: не затрагиваются этой работой.
- **Учёт товаров → Пополнение**: Тип операции (Производство/Возврат/Заказ у поставщиков), Товар, Количество, Примечание. Форма явно предупреждает: "Запись товара с типом Производство влечёт списание Материалов со склада".
- **Учёт товаров → Перемещение**: не осмотрено детально, не затрагивается этой работой.

### Существующие Apps Script файлы (папка `AppScripts/`)

Имена файлов не соответствуют содержимому (легаси-путаница, менять не обязательно):

- `OrderHandler.gs` — на самом деле: Telegram-уведомления при отправке формы (Продажа/Расход/Доход/Переводы), ежедневный отчёт в 8:00, Telegram-бот вебхук (`/баланс`, `/отчет`).
- `ProductionHandler.gs` — на самом деле: обработка денежных переводов между счетами (`handleTransfer`), пишет зеркальную строку зачисления + комиссию в "Ответы на форму (1)".
- `Переводы.gs` — на самом деле: автосписание материалов при производстве (`handleProduction`, `onEditProduction`, `writeOffMaterials`). Читает BOM из "Справочники" (столбцы M:P), проверяет достаточность остатка материалов, пишет списания в "Реестр материалов".
- `Уведомления.gs` — Telegram-уведомления о новых заказах из "Заказы клиентов" + напоминание за 2 часа до доставки.

**Обнаруженный баг**: `onEditProduction` в `Переводы.gs` слушает изменение столбца **3** (`C` = "Тип записи") в листе "Реестр товаров", но значение "Производство" по факту вводится в столбец **6** (`F` = "Тип"). Похоже на рассинхронизацию после того, как в лист добавили столбцы `ID`/`Тип записи`. Пользователь не уверен, работает ли сейчас автосписание при ручном вводе — считаем багом, чиним и тестируем в рамках этой работы.

## Проблемы, которые решает эта работа

1. **Нет инструмента инвентаризации.** Чтобы выровнять остаток под фактический подсчёт, сейчас нужно вручную вычислять и вписывать корректирующую дельту в реестр. Хочется просто вписать фактическое количество по каждой позиции.
2. **Списание при продаже неудобно**, поэтому на практике вписывается только доход деньгами, а остатки товаров не ведутся — накапливается расхождение с реальностью (в остатках уже есть отрицательные значения, например "О маме" −3 на Основном складе).
3. **Форма для продаж негибкая**: один товар за раз, без корзины из нескольких позиций, без видимости остатка на месте ввода.

Пользоваться новыми инструментами будут только владелец и партнёр (у обоих отдельные Google-аккаунты), **в основном с телефона**.

## Дизайн

### Архитектура

Отдельное **Google Apps Script Web App** (`doGet()`, HTML/CSS/JS), развёрнутое из того же скрипт-проекта, что уже привязан к таблице (переиспользует доступ к `SpreadsheetApp`). Открывается по прямой ссылке в любом мобильном браузере; можно добавить на домашний экран телефона.

- Развёртывание: "Выполнять от имени: меня" / "Доступ: любой с Google-аккаунтом".
- Внутри скрипта — проверка `Session.getActiveUser().getEmail()` по списку из двух адресов (владелец + партнёр). Для всех остальных — экран "Нет доступа".
- Меню внутри самой таблицы не добавляем — единственная точка входа это ссылка на веб-приложение.
- Функционально не работает офлайн (нужен интернет — как и сама Google Таблица).

### Инструмент 1: Инвентаризация

**Экран выбора**: Материалы, или Товары (для товаров — дополнительно выбор локации: Основной склад или одна из 5 точек).

**Экран подсчёта**: список позиций (Материал/Товар, единица измерения) с текущим расчётным остатком и пустым полем "Факт". Мобильная раскладка — один столбец, крупные поля, числовая клавиатура. Позиции без изменений оставляются пустыми.

**Сохранение**: для каждой заполненной строки считается `дельта = факт − текущий остаток`. Строки с дельтой 0 или пустым полем пропускаются (без записи в журнал, чтобы не засорять его).

- **Материалы** → строка в "Реестр материалов": `Тип = "Приход"` (дельта > 0) или `"Списание"` (дельта < 0), `Количество = |дельта|`, `Примечание = "Инвентаризация от {дата}"`. Формула остатка не меняется — уже поддерживает эти два типа.
- **Товары** → строка в "Реестр товаров": новый `Тип = "Инвентаризация"`, `Куда = локация` (дельта > 0) или `Откуда = локация` (дельта < 0), `Количество = |дельта|`. **Требуется расширить формулу остатка** в "Склад товаров" (по всей сетке Товар×Локация) двумя дополнительными слагаемыми СУММЕСЛИМН — по аналогии с "Возврат".

### Инструмент 2: Корзина продаж

**Шаг 1 — точка/канал**: выбор из справочника "Точки продаж" (Instagram, Основной склад, Teplo Store TAS/SKD, Human House, UzPost, Ethno Gallery, Маркеты).

**Шаг 2 — корзина**: список товаров из "Справочник цен" с остатком именно в выбранной точке. Добавление позиции + количество; мягкое предупреждение при нехватке остатка (не жёсткий запрет — продажи иногда вносятся задним числом). Цена подставляется из прайса, редактируется вручную. Отдельно — возможность добавить свободную позицию (название + цена вручную, без привязки к каталогу и остаткам) для уникальных индивидуальных альбомов.

**Шаг 3 — оплата и примечание**: тип оплаты (влияет на счёт зачисления), необязательное примечание.

**Оформление заказа** (одно нажатие, одна транзакция):
- по одной строке на позицию корзины в "Реестр товаров": `Тип записи = "Продажа"`, `Тип = "Продажа"`, `Товар`, `Количество`, `Откуда = выбранная точка`;
- одна строка в "Операции": `Тип = "Доход"`, `Сумма = сумма корзины`, `Счёт` (по карте Тип оплаты → Счёт из "Справочники"), `Категория = "Продажа товаров"`, `Примечание` = список позиций;
- Telegram-уведомление в том же формате, что сейчас шлёт форма при продаже (сохраняем привычный UX для тех, кто читает канал).

Этот инструмент **полностью заменяет ветку "Продажа"** в Google-форме. Ветки Расход/Доход/Переводы/Учёт товаров в форме не меняются.

### Попутное исправление

Поправить `onEditProduction` в `Переводы.gs`: слушать столбец `F` ("Тип"), а не `C` ("Тип записи"), чтобы ручной ввод "Производство" в "Реестр товаров" действительно списывал материалы. Проверить и `handleProduction` (form-submit версию) на соответствие текущей структуре листов.

## Вне объёма (сознательно не делаем)

- Мобильное приложение вне браузера (нативное iOS/Android).
- Изменение веток формы Расход/Доход/Переводы/Учёт товаров → Перемещение.
- Изменение логики расчёта BOM/себестоимости как таковой — только чиним триггер, который её вызывает.
- Поддержка офлайн-режима.

## Открытые вопросы для этапа реализации

- Точный email партнёра для списка доступа (уточнить у пользователя перед развёртыванием).
- Точная структура столбцов "Операции" (в частности, назначение столбца "Количество") — свериться перед тем, как писать туда новую строку дохода.
- Разметка BOM в "Справочники" (столбцы M:P) — свериться с `writeOffMaterials`, что колонки не съехали так же, как съехал `onEditProduction`.
- Нужно ли форме оставить ветку "Продажа" полностью удалённой, или временно скрытой (на случай отката) — уточнить перед изменением формы.

## Критерии готовности

- Инвентаризация: тестовый прогон по 2–3 позициям материалов и товаров (в т.ч. на локации-точке), остатки после сохранения совпадают с введённым фактом, лишние строки не создаются для пустых полей.
- Корзина: тестовая продажа из 2+ позиций с одной точки, после оформления — остаток по точке уменьшился на нужное количество, в "Операции" появилась одна строка с верной суммой и счётом, Telegram-уведомление пришло.
- Баг с `onEditProduction`: ручной ввод "Производство" в "Реестр товаров" действительно списывает материалы по BOM и корректно блокирует при нехватке.
- Доступ: сторонний Google-аккаунт (не из списка) видит экран "Нет доступа".
